## Первые результаты для Galahad II LCDV2

Пути в этом разделе относительны новому каталогу декомпиляции.

1. **Набор имён файлов Core/Galahad2Vision не изменился** относительно
   старой декомпиляции. Имена и числовые значения `Commands` совпадают;
   `RequestType` и `SettingType` имеют тот же набор и порядок элементов.
   Это ещё не доказательство byte-for-byte совместимости всех команд:
   тела методов и firmware branching требуют отдельного сравнения.

2. **Cooling loop остаётся в сервисе.**
   `L-Connect-Service/LConnectService/Products/Galahad2Vision/Galahad2VisionController.cs:315–380`
   содержит расчёт fan/pump speed и отправку PWM. Решение размещать
   Linux curves в daemon подтверждено свежим reference.

3. **Streaming выбирает framing по firmware.** В том же controller,
   строки 1249–1281, для FW >= 1.5 выбирается `SendH264Frame512`.
   `L-Connect.Core/LConnectCore/Products/Galahad2Vision/Galahad2VisionDevice.cs:168–171,221–224`
   показывает B-command 13 для обычного метода и C-command 13 для 512-byte
   метода; затем читается ответ 512 bytes с timeout 20 ms.
   Такая ветка была и в старой декомпиляции: это подтверждение, не новая
   функция 2.1.28. Linux имеет оба codec builders, но playback pipeline
   пока отсутствует. Для исторически зафиксированной FW 1.6 исследовать
   прежде всего C-framing, предварительно повторно прочитав текущую FW.

4. **Найдена дополнительная thermal-alert интеграция.** Новый controller
   реализует `IThermalAlertAwareController`, регистрируется в
   `TemperatureAlertController` и содержит override/restore lighting
   (`Galahad2VisionController.cs:1283,1288,1680–1740`). В старом файле
   этих интерфейса/регистраций не найдено.
   `L-Connect-Service/LConnectService/Products/TemperatureAlert/TemperatureAlertController.cs`
   содержит CPU/GPU sources, enabled/threshold, alert colors и restore.
   Добавить в LCDV2 parity matrix сценарий: температурное предупреждение
   временно меняет подсветку, затем восстанавливает её; проверить взаимодействие
   с ручным применением RGB. Включённость функции и доступность настройки
   в UI этой Windows-установки ещё требуют сквозного подтверждения.

Следующая исследовательская работа: проследить UI → request/settings → service
→ device для каждой LCDV2-функции, включая firmware, media и thermal alerts.
Наличие enum без caller не считать пользовательской возможностью.

## ll-connect3: что полезно

Источник: [joeytroy/ll-connect3](https://github.com/joeytroy/ll-connect3).
Локальный read-only reference checkout:
`/home/inky/Development/lian-li/scratch/ll-connect3-reference-2026-09-08`.
Зафиксированный commit: `a2f2d68d48a0515d19631e88123b8aeb7ec3896b`
(2026-08-29). Проверка состояла в чтении исходников, без сборки, запуска
installer и загрузки kernel module.

Это C++/Qt-приложение для SL-Infinity с kernel fan driver и userspace
USB/HID-компонентами. Kernel driver заявляет `0x0CF2:0xA102`, наш LCDV2 —
`0x0416:0x7395`. Его packet layouts не применимы к LCDV2 по умолчанию.

| Источник | Практическая польза |
|---|---|
| `src/pages/fanprofilepage.cpp`, `src/widgets/fancurvewidget.cpp` | Редактор точек кривой, presets/custom slots, Apply to All, фильтрация температуры и ограничение изменений RPM |
| `src/pages/systeminfopage.cpp` | Примеры получения Linux telemetry через hwmon, thermal zones, sensors и GPU tools |
| `src/pages/settingspage.cpp` | UX сохранения/экспорта настроек, labels, единицы, startup options |
| `src/usb/sl_infinity_hid.cpp` | Дополнительный reference для будущей SL-INF реализации, не LCDV2 |
| `kernel/`, `install.sh`, `.github/` | Опыт DKMS, дистрибуции и CI; kernel-specific требования обусловлены их архитектурой |

## Что не переносить как образец надёжности

- `FanProfilePage::updateTemperature`, строки 639–663: после неудачи чтения
  CPU/GPU подставляется искусственно меняющаяся температура. Она попадает в
  `m_cachedTemperature`, используемую `controlFanSpeeds` (около строки 1203).
  В Linux daemon нужны явно unavailable/stale и определённый fallback.
- Timers и управление кривыми находятся в Qt page object. Это не отдельный
  автономный daemon; закрытие/жизненный цикл GUI нельзя брать за основу
  гарантии непрерывного охлаждения.
- `systeminfopage.cpp` многократно использует `QProcess::waitForFinished(1000)`.
  Наши sensor providers должны выполняться вне UI и не задерживать HID-loop.
- Kernel module и `/proc` API не являются необходимым условием нашего
  проекта: существующий userspace HID daemon уже обслуживает LCDV2.

Root LICENSE содержит GPL-2.0 text; `sl_infinity_hid.cpp` явно маркирован
`GPL-2.0-or-later`. Аудит не устанавливает лицензионный статус каждого файла.
Код не копировался; перед заимствованием конкретного файла нужно учитывать
его собственные notices и provenance.

## Изменение roadmap

- Новый основной Windows baseline — локальный **2.1.28.0**; задача получения
  свежего reference закрыта для перечисленных сборок.
- Сравнение применимых LCDV2-сценариев с 2.1.11 остаётся работой R0.
- Thermal alert добавлен в исследуемые сценарии R1/R6.
- ll-connect3 добавлен как источник UX/Linux integration и будущего SL-INF
  research. Он не расширяет текущий hardware scope.
- Активная цель по-прежнему LCDV2; других устройств для проверки нет.
