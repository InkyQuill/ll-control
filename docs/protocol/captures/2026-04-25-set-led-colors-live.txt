## set-led-colors --color '#0000FF' --kind fan --yes

→ Partial render: 2 of 3 fans rendered blue. The last fan retained its
  previous cmd-133 (SetFanLighting) red state from a Phase 0c test. The
  fan ring on this build is an aggregate of N × 16 LEDs in series; with
  --count 16 we wrote only the first 16 (= the first 1.0 fans), leaving
  the remaining ~32 LEDs at their last-set state. To paint a 3-fan
  configuration uniformly, --count 48 would be required. The codec is
  faithful; this is a configuration-discovery moment.

## Notes

- Cmd 20 renders are immediate at the cadence tested; no buffering or
  rate-limiting issue observed on the screen path.
- Cmd 20 supersedes cmd 131 in the LED render pipeline. The pump cap
  was held at magenta from a prior cmd 131 (SetPumpLighting) write;
  the first cmd 20 write to red overrode that state cleanly.
- The default --count of 16 matches the LCDV2 pump-cap screen ring's
  physical LED count exactly.
- The fan ring is an aggregate of multiple fans' LEDs in series. The
  per-fan count appears to be 16 (consistent with the SKU); the user's
  setup appears to have 3 fans (~48 LEDs total in the aggregate).
- The --set-application-mode flag was NOT exercised in this session;
  all cmd 20 writes rendered without it. The flag remains a "try this
  if no visible change occurs" escape hatch but is not required on
  firmware 1.6.
