Bugs surfaced
-------------

[ISSUE 1] CRITICAL -- FIXED MID-RUN -- commit c920aff
  Daemon wrote raw 0..=100 brightness/speed percentages directly
  into PumpLightingSetting.brightness and .speed wire bytes. The
  LCDV2 firmware expects 0..=4 (5 levels) per the verify-galahad
  Phase 0c convention `args.brightness / 25`. Out-of-range bytes
  are silently ignored, so cmd 131 (SetPumpLighting) succeeded on
  the wire but produced no visible change.

  Fix: percent_to_wire(p) = (p / 25).min(4), applied in both
  - ipc_server::set_lighting (Fan + Pump arms)
  - lighting_keeper::{fan,pump}_setting_from_state (re-issue path)

  The Phase 1 test for lighting_keeper (P1D-7) used MockBackend
  and asserted on the cmd byte at offset 1 but not the brightness
  / speed byte values, which is why the bug shipped. Adding a
  byte-level fixture comparison against verify-galahad's known-
  good output is a good Phase 2 test-suite improvement.

[ISSUE 2] LOW -- daemon HID-write counter undercounts
  stats::Stats::inc_hid_write only fires from IpcServerImpl's
  write_and_wait / write_read_* helpers. Keeper-driven writes
  (lighting_keeper, lcd_keeper) bypass the counter. Functionally
  fine -- writes still succeed -- but observability is incomplete.

  Fix scoped: move stats::inc_hid_write into the hid_io actor
  itself so every successful HID write counts uniformly.
  Not blocking; consider for a Phase 1 follow-up commit or roll
  into Phase 2 work.

[ISSUE 3] MEDIUM -- clear_lcd is silent
  See lcd clear test note above. Filed as task #132.

Bottom line
-----------
The daemon, CLI, and protocol codecs all work end-to-end against
the user's actual Galahad II LCDV2. The one Critical bug found
during the smoke (the brightness/speed wire-conversion mismatch)
is fixed and committed. The two remaining issues (lcd clear,
stats counter) are tracked but non-blocking. Phase 1 is in a
shippable state for a development build.
